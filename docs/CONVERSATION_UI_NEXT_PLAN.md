# 会话式收发第二阶段改造计划

- 日期：2026-11-07
- 状态：C1–C2 已实施，C3–C8 待实施
- 基线：`12246bfa`（P10 文案）及当前 `37173a30`（收藏设备自动接收、进入会话时刷新设备）
- 前序方案：[会话式收发界面改造方案](CONVERSATION_UI_PLAN.md)

## 1. 目标和实施范围

用户打开一台设备的会话后，可以连续发送文字和附件，知道文件传到了哪一步，直接处理失败，并点开收到的图片或文件。桌面参考 Flix 的两层输入区，输入框占一行，常用附件入口和发送键位于下一行。宽屏沿用设备列表与会话详情两栏，窄屏沿用列表进入详情。

本计划以 `C1` 至 `C8` 编号，与原方案的 P 批次分开。P11 全量回归及跨端验收由用户手动完成。各批次的完成条件用于界定行为，实施时可用既有相关测试做定向验证。

- 复用现有 Flutter、Refena、Dart 收发服务、平台选择器和打开文件能力。保留原发送、接收、链接分享和 WebRTC 路径。遵守仓库 `AGENTS.md` 的贡献约束。
- 会话仍按设备指纹区分，发送目标保留最新可用设备地址及 IPv6 scope，继续使用已有指纹校验。会话切换、返回、缩放和清空记录均与取消传输独立。
- 会话历史仍是有界的本地记录。草稿、任务令牌、进度、临时选件路径、附件字节和预览缓存均留在运行时；历史开关和清除语义沿用现有实现。
- 截图、独立视频选择或播放、离线投递、已读回执和图文同条暂列后续议题。当前文字走单个内存文本文件的 `preview` 路径，附件批次单独发送。剪贴板入口若复用现有能力，须由用户主动点击并预览内容。

## 2. 当前实现与优先级

| 现状 | 对会话体验的影响 | 对应批次 |
| --- | --- | --- |
| P9b 把附件写入 `selectedSendingFilesProvider`，要求旧选件和发送 session 都为空。普通文件后台成功时 `_finish` 在 `sending` 状态直接关闭 session，`closeSession` 的旧选件清理只在 `finished` 且单发模式下发生。 | 文件成功后下一次选件仍可能禁用。保留的失败任务也会禁用附件入口。 | C1、C2 |
| 发送气泡消费阶段和终态摘要，实时上传进度及单文件重试仍由原发送进度页使用。 | 看见失败之后，无法直接在气泡处理。 | C2 |
| 详情气泡里的文件只有图标和信息，已有 `ConversationFileThumb` 尚未接入。接收摘要保留保存结果，发送摘要的 `path` 为空。 | 收到的内容需要从其他入口打开，图片在时间线上不易辨认。 | C3 |
| 会话收藏免确认当前使用 `certFingerprint ?? info.fingerprint` 的结果匹配收藏。 | 无证书时，对端自报指纹也可能触发会话收藏免确认。 | C4 |
| 输入栏单行放置回形针、文字框和发送键，选完附件立即发。首页桌面拖入文件会切换到旧发送页。 | 常用附件入口不直观，拖入内容也无法先检查收件设备和文件。 | C5、C6 |
| 左栏优先按在线状态排序，最后一条附件摘要统一显示为文件，活动用转圈提示。 | 附近设备变化会移动已有会话，待确认请求也不容易辨认。 | C7、C8 |

实施顺序建议为 **C1 → C2 → C3**，先交付会话内收发闭环。C4 可独立实施，须先于 C7 的收藏免确认提示。之后按 **C5 → C6 → C7 → C8** 推进。C5 可以在 C1 完成后提前实施。

## 3. 分批实施

### C1 · 让会话附件连续可发

入口：`app/lib/provider/conversation_attachment_provider.dart`、`app/lib/util/native/file_picker.dart`、`app/lib/provider/selection/selected_sending_files_provider.dart`、`app/lib/provider/network/send_provider.dart`。缓存入口为 `app/lib/util/native/cache_helper.dart`。

1. 把会话需要的选择结果从旧选件中分离。先梳理各平台 picker 的返回值、目录展开、文件转换和缓存来源；提取会话可直接消费的结果路径，并保留 `PickFileAction` 原有入口。C1 先沿用选完立即发送的交互，C6 再接待发区。目录继续复用 `.sendignore` 与相对路径逻辑。
2. 选择开始时记录目标 peerKey，完成后重新读取该设备及可用地址，校验目标一致且在线，再把不可变选件快照交给 `startSession`。选择取消或结果为空时释放本次锁。失败保留可处理状态；退出或切换页面期间按实际资源所有权清理。
3. 发送任务记录选件来源或等价的所有权信息，让会话任务的关闭只释放它拥有的资源。成功、取消、明确结束和不可重试失败释放资源；允许重试的文件保留到重试结束或用户结束任务。调用 `ClearSelectionAction` 会触发全局 `ClearCacheAction`，因此不能靠提前调用它释放会话选件。对临时文件、Android URI、相册资源分别验证可用性及生命周期；共享清理可能触及会话缓存时，先解决隔离或明确缩小接入范围。
4. 启用条件只看当前选择操作及会话实际资源占用。允许其他设备或旧发送页独立使用其选件。仍需限制并发时，以实际会话任务为单位，提供明确禁用原因。实现分为 **C1a 选择器结果接口** 和 **C1b 会话所有权及关闭清理**，按平台逐项切换。

完成条件：同一设备连续发送两批普通文件；全局已有旧选件时会话发送不污染旧选件；一次取消、拒绝、选件异常或任务关闭后能再次选择。上传或重试期间所属文件仍可读取，切设备时附件不串到另一台设备。

### C2 · 在发送气泡中显示进度并处理失败

入口：`app/lib/pages/tabs/conversation_tab.dart`、`app/lib/widget/conversation/conversation_entry_tile.dart`、`app/lib/provider/network/conversation_send_recorder.dart`、`app/lib/provider/file_transfer_provider.dart`。对照 `app/lib/pages/progress_page.dart` 的取消与 `sendFile` 重试调用。

- 用会话记录的方向和 `localSessionId` 匹配当前发送任务，在对应气泡订阅所需进度。校验和、等待确认和上传分别呈现，上传百分比以对方实际接受的文件为分母。历史记录只存阶段和最终结果。
- 等待或上传时提供「取消发送」。仅当前失败文件、有效远端 token 和存活 session 同时满足时提供「重试」，复用 `sendFile(isRetry: true)`，防止重复提交。远端已结束或任务已释放时，隐藏原任务重试；如提供「重新发送」，需重新验证源材料并创建新任务。
- 终态气泡区分「结束任务」和「取消发送」。结束失败任务后保留失败摘要；同一任务重试更新原气泡。核对准备请求返回空文件集合的分支，保留文字确认成功语义，文件批次没有被接收时单独呈现结果，避免显示「已完成」且文件一直待处理。同步检查现有 locale 和历史兼容性。

完成条件：一批文件部分失败后，能从原气泡重试或结束。重试后只保留一张任务卡片。取消动作只影响点中的发送任务；同设备的接收请求、其他设备的任务和旧页面路径仍独立。

### C3 · 在会话内预览收到的图片、打开文件

入口：`app/lib/widget/conversation/conversation_entry_tile.dart`、`app/lib/widget/conversation/conversation_file_tile.dart`、`app/lib/provider/network/conversation_receive_recorder.dart`。复用 `app/lib/util/native/open_file.dart` 与 `open_folder.dart`。

- 成功收到且有可读本地路径的图片显示有尺寸上限的缩略图，保持比例，点按打开大图。复用现有解码尺寸限制和加载失败回退。首批可做单图与多图逐项展示，视频保留文件卡片。
- 成功收到的普通文件提供「打开」。桌面本地路径提供「在文件夹中显示」。Android `content://` 交由现有 URI 打开逻辑；仅有相册保存结果时显示对应提示。文件缺失或无权限时提示原因，历史记录仍可查看。
- 发送侧历史摘要当前不含源路径，首批保持文件卡片；后续若要显示发出图片，可先评估运行时预览和跨重启预览各自需要的缓存与隐私边界。

完成条件：重启后仍能打开已保留路径且可访问的接收文件；移动原文件、URI 不可读或图片解码失败时有可理解的回退；清空会话记录后实际文件仍在。

### C4 · 收紧会话收藏设备的免确认条件

入口：`app/lib/provider/network/server/controller/receive_controller.dart`、`app/lib/model/conversation/transfer_presentation.dart`、`app/test/unit/model/transfer_presentation_test.dart`。

- 会话的收藏免确认规则只匹配本次请求经过验证的 `event.certFingerprint`。证书缺失或指纹不匹配时，这条规则不触发。发送方名称展示和历史身份沿用各自的现有逻辑。会话与 legacy 各自的快速保存设置仍按已有规则执行，界面区分「收藏设备免确认」和「快速保存」。
- 用现有收藏数据与指纹比较，无需新增好友协议或互关字段。自动接收是接收端单向决定，双方分别收藏并满足接收条件时才能双向免确认。

完成条件：有效证书指纹命中收藏时，文件和文字仍能自动接收；仅对端自报同一收藏指纹时，收藏规则不放行；陌生设备继续按已有接收设置处理。

### C5 · 调整输入区和常用附件入口

入口：`app/lib/widget/conversation/conversation_composer.dart`、`app/lib/widget/conversation/conversation_panel.dart`、`app/lib/pages/tabs/conversation_tab.dart`。

- 输入框独占一行，下一行左侧是附件工具栏、右侧是发送键。桌面直出「文件」「文件夹」，移动端按 `FilePickerOption.getOptionsForPlatform` 露出「相册」等现有能力，空间不足时收进更多菜单。C6 落地前，用按钮提示说明当前是选完即发。
- 桌面 `Enter` 发送、`Shift+Enter` 换行；中文输入法合成中的回车优先确认候选词。移动端保留系统换行和点击发送。空文本禁用发送，保留非空原文及换行；离线可编辑草稿，重连后由用户手动发送。
- 为纯图标按钮提供 tooltip 和语义标签，沿用现有主题。新文案补齐 `en`、`zh-CN`、`zh-HK`、`zh-TW`，使用 `fvm dart run slang` 生成。

完成条件：键盘和鼠标都能完成发送，切换设备后恢复各自的文字草稿；窄屏、软键盘打开或窗口缩小后，输入区和消息列表仍可用。

### C6 · 加入待发送附件区和会话内拖放

入口：C1 的独立选件流程、`app/lib/widget/conversation/conversation_composer.dart`、`app/lib/pages/home_page.dart`。依赖 C1、C5。

- 选择的附件先在当前设备会话显示名称和数量，支持逐项移除。发送前检查目标仍在线，并提交该设备附件快照。待发区按 peerKey 保存在内存。清空草稿、切换目标和成功提交时，各自按所属资源处理。
- 当前会话详情拥有桌面拖放目标时，将内容交给当前会话的待发区，展示明确的目标设备。只由一个拖放入口消费同一次操作。没有选中会话时显示提示；其他标签页沿用原拖放入口。
- 文字和附件同时存在时，发送键先提交附件批次，保留文字草稿并提示可单独发送文字；待发区明确显示这一行为。以后如需支持一条图文消息，再单独设计协议及兼容策略。

完成条件：拖入、移除、取消、换设备都不会发出文件；点击发送只提交当前设备的附件；导入目录保留相对路径和忽略规则；选件过程中设备离线时，用户仍能检查待发内容。

### C7 · 整理最近会话、待确认和收藏入口

入口：`app/lib/provider/conversation_view_provider.dart`、`app/lib/widget/conversation/conversation_list.dart`、`app/lib/widget/conversation/conversation_panel.dart`、`app/lib/provider/favorites_provider.dart`。依赖 C4 的收藏免确认规则。

- 已有记录或待处理的设备归入「最近会话」，其余发现设备归入「附近设备」。待确认请求优先提示；最近会话按最后活动时间稳定排序，在线状态独立显示。列表项展示最后一条文字或附件摘要及本地时间，待确认与传输中用不同标签。
- 在详情菜单加入收藏及取消收藏，复用已有动作和别名。显示收藏免确认所需条件。收到其他设备的请求时，给出可定位到对应会话的提示，保留当前输入与选中状态，等待用户主动进入。

完成条件：设备上下线时仍能定位已有会话；待确认请求与普通传输容易区分；同指纹多地址只出现一条；进入对应会话后可操作实际匹配的接收请求。

### C8 · 完善消息时间线和滚动

入口：`app/lib/widget/conversation/conversation_panel.dart`、`app/lib/widget/conversation/conversation_entry_tile.dart`。可在 C2、C3 完成后独立进行。

- 为消息使用稳定 `entryId`，按本地日期或时间间隔插入时间标签。发出和收到的消息继续左右区分，正常完成的状态弱化，等待、失败和取消仍清晰。收件确认卡片继续核对方向与 sessionId。
- 打开会话时定位最新内容。已在底部附近时跟随新消息，查看旧记录时保持位置并显示「回到最新」。更新已有消息的进度或终态时维持当前位置；主动发送时回到自己刚提交的消息。

完成条件：浏览旧消息期间收到新内容或进度变化时，视口稳定；长文字展开状态不会串到其他消息；切换设备和宽窄屏后仍能回到可理解的阅读位置。

## 4. 实施交接

- 一次处理一个批次；需要同时调整资源所有权和用户交互时，先拆基础接口再接界面。每批交接记录实际变更、针对性验证、仍待用户手测的行为及下一批依赖。
- 优先复用 `conversation_attachment_provider_test.dart`、`conversation_send_recorder_test.dart`、`conversation_panel_test.dart`、`conversation_composer_test.dart` 和 `transfer_presentation_test.dart`。文件位于 `app/test/` 的现有分类中。涉及持久化时同时检查旧记录兼容、历史开关及清空行为。
- 定向命令从 `app/` 执行，使用 `fvm flutter test <对应测试文件>` 和 `fvm dart format <改动文件>`。涉及文案时补跑 `fvm dart run slang` 与 `fvm flutter test test/unit/i18n_test.dart`。平台选择器、URI、实际设备互传及跨端回归保留给用户手动确认。

### C1 桌面子批 · 2026-11-07

- 会话选择器复用现有桌面选件转换和目录展开。每次选择使用独立的内存选件容器，提交时复制快照，桌面会话关闭时跳过旧发送页的全局选件清理。旧发送页可以保留自己的选件。
- 选件完成后按初始设备指纹读取当前地址。找不到该设备时结束本次选件。遗留失败任务不占用下一次选择器。会话仍使用即选即发。
- 定向测试覆盖独立剪贴板选择、连续提交两批附件、目标地址更新及 IPv6 scope、目标离线和任务关闭时保留旧选件。真实选择器及设备互传留待手测。

### C1 移动端子批 · 2026-11-07

- 移动端选择器沿用已有平台入口，每次选择只写自己的选件容器。Android 文件和目录保留 SAF URI，沿用系统提供的读取授权；APK 选择页把本次结果交回会话选择器。文字与剪贴板路径沿用现有转换。
- iOS 导入文件和相册等临时来源在发送前复制到每次任务独立的应用缓存目录。会话成功、取消或不可重试时释放副本，正在读取的任务先结束读取；允许重试的任务保留副本。旧发送模式切换只处理旧发送任务。
- 定向测试覆盖 Android 选件与旧选件隔离、继续选件、取消解锁、临时目录清理后仍可读、任务结束后释放副本，以及旧发送模式切换时保留会话任务。iOS 相册、Android 文件授权及实际设备互传留待手测。下一批为 C2。

### C2 发送气泡 · 2026-11-07

- 发送气泡分别显示校验和、等待确认和上传阶段。上传进度以对端接受的文件为范围，文件大小未知时按文件数计算。
- 可从气泡取消进行中的发送，逐个重试失败文件，或结束失败任务并保留历史结果。重试更新原气泡，接收端明确拒绝令牌或上传路径时收起该文件的重试入口。
- 附件无人接收时记录「对方未接收任何文件」，文字确认仍按成功记录。定向测试验证进度分母、重试入口和历史序列化。实际设备互传、取消和重试留待手测。下一批为 C3。
