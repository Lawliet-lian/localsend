## 1. 目标和实施范围

用户打开一台设备的会话后，可以连续发送文字和附件，知道文件传到了哪一步，直接处理失败，并点开收到的图片或文件。输入区保持单行排列，按平台提供常用附件入口。宽屏沿用设备列表与会话详情两栏，窄屏沿用列表进入详情。

本计划以 `C1` 至 `C8` 编号，与原方案的 P 批次分开。P11 全量回归及跨端验收由用户手动完成。各批次的完成条件用于界定行为，实施时可用既有相关测试做定向验证。“已实施”表示代码已落地；自动检查、设备手测和最终验收分别记录，未执行的检查不得计为通过。

本文件是第二阶段的执行入口。前序方案保留 P 批次的设计与历史证据；C1–C3 对选件所有权、文件预览及 Android 相册保存的调整以本文为准。

- 复用现有 Flutter、Refena、Dart 收发服务、平台选择器和打开文件能力。保留原发送、接收、链接分享和 WebRTC 路径。遵守仓库 `AGENTS.md` 的贡献约束。
- 会话仍按设备指纹区分，发送目标保留最新可用设备地址及 IPv6 scope，继续使用已有指纹校验。会话切换、返回、缩放和清空记录均与取消传输独立。
- 会话历史仍是有界的本地记录，允许保存接收结果和发送图片的来源路径或 URI。草稿、任务令牌、实时进度、附件字节和解码缓存留在运行时；历史开关和清除语义沿用现有实现。临时上传副本不能作为可靠的长期预览来源，当前回退路径仍可能记录临时位置，见 C3 遗留项。
- C3 按本轮需求增加发送图片预览，并修改 Android 原生方法通道及 `localsend_isolates` 的相册保存辅助函数。该辅助函数由新旧接收入口共用，因此 legacy 相册保存也在回归范围内。
- 截图、独立视频选择或播放、离线投递、已读回执和图文同条暂列后续议题。当前文字走单个内存文本文件的 `preview` 路径，附件批次单独发送。剪贴板入口若复用现有能力，须由用户主动点击并预览内容。

## 3. 分批实施

### C1 · 让会话附件连续可发

入口：`app/lib/provider/conversation_attachment_provider.dart`、`app/lib/util/native/file_picker.dart`、`app/lib/provider/selection/selected_sending_files_provider.dart`、`app/lib/provider/network/send_provider.dart`。缓存入口为 `app/lib/util/native/cache_helper.dart`。

1. 把会话需要的选择结果从旧选件中分离。先梳理各平台 picker 的返回值、目录展开、文件转换和缓存来源；提取会话可直接消费的结果路径，并保留 `PickFileAction` 原有入口。C1 先沿用选完立即发送的交互，C6 再接待发区。目录继续复用 `.sendignore` 与相对路径逻辑。
2. 选择开始时记录目标 peerKey，完成后重新读取该设备及可用地址，校验目标一致且在线，再把不可变选件快照交给 `startSession`。选择取消或结果为空时释放本次锁。失败保留可处理状态；退出或切换页面期间按实际资源所有权清理。
3. 发送任务记录选件来源或等价的所有权信息，让会话任务的关闭只释放它拥有的资源。成功、取消、明确结束和不可重试失败释放资源；允许重试的文件保留到重试结束或用户结束任务。调用 `ClearSelectionAction` 会触发全局 `ClearCacheAction`，因此不能靠提前调用它释放会话选件。对临时文件、Android URI、相册资源分别验证可用性及生命周期；共享清理可能触及会话缓存时，先解决隔离或明确缩小接入范围。
4. 启用条件只看当前选择操作及会话实际资源占用。允许其他设备或旧发送页独立使用其选件。仍需限制并发时，以实际会话任务为单位，提供明确禁用原因。实现分为 **C1a 选择器结果接口** 和 **C1b 会话所有权及关闭清理**，按平台逐项切换。

完成条件：同一设备连续发送两批普通文件；全局已有旧选件时会话发送不污染旧选件；一次取消、拒绝、选件异常或任务关闭后能再次选择。上传或重试期间所属文件仍可读取，切设备时附件不串到另一台设备。

### C2 · 在发送气泡中显示进度并处理失败

入口：`app/lib/pages/tabs/conversation_tab.dart`、`app/lib/widget/conversation/conversation_entry_tile.dart`、`app/lib/provider/network/conversation_send_recorder.dart`、`app/lib/provider/file_transfer_provider.dart`。对照 `app/lib/pages/progress_page.dart` 的取消与 `sendFile` 重试调用。

- 用会话记录的方向和 `localSessionId` 匹配当前发送任务，在对应气泡订阅所需进度。校验和、等待确认和上传分别呈现，上传百分比以对方实际接受的文件为分母。历史记录只存阶段和最终结果。
- 等待或上传时提供「取消发送」。仅当前失败文件、有效远端 token 和存活 session 同时满足时提供「重试」，复用 `sendFile(isRetry: true)`，防止重复提交。远端已结束或任务已释放时，隐藏原任务重试；如提供「重新发送」，需重新验证源材料并创建新任务。
- 终态气泡区分「结束任务」和「取消发送」。结束失败任务后保留失败摘要；同一任务重试更新原气泡。核对准备请求返回空文件集合的分支，保留文字确认成功语义，文件批次没有被接收时单独呈现结果，避免显示「已完成」且文件一直待处理。同步检查现有 locale 和历史兼容性。

完成条件：一批文件部分失败后，能从原气泡重试或结束。重试后只保留一张任务卡片。取消动作只影响点中的发送任务；同设备的接收请求、其他设备的任务和旧页面路径仍独立。

### C3 · 在会话内预览收发图片、打开文件

状态：主要功能及用户反馈修复已实施，自动检查已通过，设备验收待完成。

入口：`app/lib/widget/conversation/conversation_entry_tile.dart`、`conversation_file_tile.dart`、`app/lib/widget/file_thumbnail.dart`、`app/lib/provider/network/conversation_send_recorder.dart`、`send_provider.dart`。接收结果继续由 `conversation_receive_recorder.dart` 写入；文件操作复用 `app/lib/util/native/open_file.dart` 与 `open_folder.dart`。

Android 相册入口：`app/android/app/src/main/kotlin/org/localsend/localsend_app/MainActivity.kt`、`packages/localsend_isolates/lib/util/android_channel.dart`、`lib/src/task/server/file_saver.dart`（后两者属于 `localsend_isolates` 包）。

- 接收成功且有路径的图片，以及有来源路径的发送图片，显示 220 逻辑像素预览框，按比例完整显示。图片分支隐藏文件名；多图逐项展示，视频仍为文件卡片。
- 点按进入统一黑底大图页，图片占用整页可用区域，左上角返回箭头悬浮于安全区域内。支持最高 4 倍缩放、系统返回和桌面 Esc。取消顶部占位工具栏；图片与屏幕比例不同时允许留黑。大图解码限制在 2048×2048 内并保持比例，无法读取或解码时显示回退。
- 成功收到的普通文件提供“打开”。成功且非相册的桌面本地文件提供“在文件管理器中显示”。Android `content://` 使用 URI 打开逻辑，原生打开异常返回 Dart 后显示无法打开提示；仅有相册保存结果而无地址时显示相册提示。
- Android 10 及以上新接收的相册图片写入 `Pictures/LocalSend`，发布成功后返回 MediaStore URI 并删除临时接收文件。旧版 Android 或新保存流程失败时沿用 Gal；Gal 成功仍可能只返回相册标志而没有地址。视频与 iOS 继续按原相册流程处理。
- Android 从相册发送的图片通过 `AssetEntity.getMediaUrl()` 获取原图 URI，供历史预览使用。上传仍读取它持有的来源；进度和终态更新按 fileId 保留创建记录时选定的预览路径，避免被临时上传路径覆盖。其他发送图片当前回退到来源路径。

完成条件：新接收图片和有可读来源的发送图片能够预览、放大和返回；Android 相册图片在发送任务清理后及重启后可按授权读取；普通接收文件可打开，桌面可定位文件；缺失文件、撤销授权或解码失败有回退；清空会话记录后实际文件仍在。验收范围及暂未覆盖的平台见第 4 节 C3 交接。

### C4 · 统一设备接收确认与传输状态

状态：主要实现已写入工作区，自动检查通过；**尚未完成**，链接接收开启时的设备请求分流和真实设备验收仍待处理。

- 设备接收设置合并为「每次确认」「仅收藏设备免确认」「所有设备免确认」，文字和文件共用判断；聊天展示开关只控制展示路径。新安装默认为每次确认。升级用户先按每次确认处理，并在启动时提示选择；原设置只作为预选，选择「稍后」后仍需确认。
- 仅收藏模式下，加密请求只根据本次证书指纹匹配收藏；未加密时默认不信任自报指纹。用户可在关闭加密时开启信任选项，确认风险后才生效。所有设备免确认是用户独立选择，可自动接收陌生设备的文字和文件。PIN 仍由接收服务先校验。
- 沿用原版按接收端协议发送的方式；设备列表、当前接收状态和会话气泡用图标及颜色区分加密与明文。新会话记录保存该次协议，旧记录及无法确认协议的请求显示未知图标。记录图标支持悬停说明；加密闭锁图标按用户要求显示红色。
- 浏览器链接接收暂不改造。但当前 `serverState.webUpload` 表示上传页是否开启，不是本次请求的来源。上传页开启期间，普通设备请求也会走链接分支和旧快速保存判断，可能绕过新确认规则或导致文字和文件不一致。不能把这一状态视为 C4 安全规则已完成；后续需设计可区分来源且不依赖可伪造声明的方案，兼顾用户要求的浏览器路径。

验证记录：本会话此前执行 `fvm flutter analyze --no-pub` 通过；完整 `fvm flutter test --no-pub` 272 项通过。其后补充的发送、接收记录及历史兼容定向测试 35 项通过，覆盖新旧记录的加密状态序列化。最新图标颜色调整后静态分析通过。以上均不代表设备互传验收。

设备验收：分别测试两端加密开关、收藏匹配与否、未加密信任选项、三种接收确认模式、文字与文件、升级提示及稍后选择；检查双向互传、不同协议方向的图标、历史重启及旧记录未知状态。另需在浏览器上传页开启时验证普通设备请求的分流修复。实际设备验收目前未完成。

### C6 · 加入待发送附件区和会话内拖放

C6 将 C5 的桌面松手即发改为拖入待发区后由用户点击发送。

入口：C1 的独立选件流程、`app/lib/widget/conversation/conversation_composer.dart`、`app/lib/pages/home_page.dart`。依赖 C1、C5。

- 选择的附件先在当前设备会话显示名称和数量，支持逐项移除。发送前检查目标仍在线，并提交该设备附件快照。待发区按 peerKey 保存在内存。切换会话保留各自待发区；移除和清空只释放对应未提交资源，成功提交后把资源所有权交给发送任务。任务重试结束前不得清理其来源。预览路径和上传路径分开处理，沿用 C3 的相册 URI 规则。

#### 已知边界与收尾项

1. **旧记录不会自动补全来源。** 已记录的空路径或已删除临时副本无法从当前摘要可靠恢复，需重新发送来验证新流程。原图被用户删除、移动或授权撤销后，预览会失效。
2. **临时来源尚未完全解决。** Android 相册原图 URI 已接入；URI 获取失败、iOS 导入或其他临时来源仍可能回退到会被清理的路径。当前摘要可能持久化该路径，不能据此承诺所有发送图片跨重启可预览。进一步修复需要明确来源类型、持久访问授权或独立预览缓存的清理规则，并遵守历史开关。
3. **错误提示仍较通用。** 图片缺失、无权限和解码失败目前共用“无法打开”回退，尚未细分原因。普通文件打开及 Finder 定位失败也需要实际平台验证。
4. **多图状态与资源边界需补测。** 图片分支隐藏了文件名及原文件行的结果图标，应检查部分失败时是否足以定位失败附件。缩略图当前按宽度限制解码，极长图和 Android URI 原始字节读取仍需内存验证；大图已有 2048×2048 解码限制。
5. **发布验收未完成。** 最新修复的 Android/桌面设备复测优先于宣告 C3 完成。手测若确认新的回归，先修复并补定向验证；通过后更新本节及页首状态。
